# Public Release Plan — Author Focus v4.3 Research Lab

## Objective

Prepare a public-facing release that is credible, understandable, citable, and safe without exposing private production implementation or research data.

## Release identity

Recommended public name:

**Author Focus v4.3 Research Lab**

Recommended subtitle:

> A science-first Microsoft Word research-workbench for writing, citations, evidence, Python/Jupyter and geospatial workflows.

## What a public release page should contain

- concise product description,
- one hero screenshot,
- 60–90 second demo,
- tested capabilities,
- known limitations,
- privacy model,
- system requirements,
- exact public/private source boundary,
- benchmark version,
- checksum for distributable artifacts,
- citation instructions,
- changelog,
- and security/reporting route.

## Do not publish

- credentials or tokens,
- certificates/signing secrets,
- user manuscripts,
- private research data,
- unpublished model assets,
- private prompts/heuristics,
- or production packages whose licensing/security status has not been reviewed.

## Release notes structure

### Highlights

- unified manuscript review,
- manual correction queue,
- local-first writing workflow,
- Python/Jupyter Research Lab,
- Google Earth Engine Python workflow,
- evidence-linked manuscript concepts,
- researcher-oriented science-first interface.

### Safety and integrity

- explicit code execution,
- manual approval of scientific edits,
- protected citations/numbers/statistics,
- provenance and rollback,
- no claim that automated screening proves scientific validity or authorship.

### Tested

List only tests actually executed.

### Not yet verified

Examples:

- all Microsoft 365 channel/build combinations,
- institutional deployment,
- every Windows configuration,
- authenticated Earth Engine export across account configurations,
- live-provider behavior across all API plans.

## Zenodo readiness

Once there is a stable public artifact suitable for archiving:

1. Ensure repository metadata and CITATION.cff are correct.
2. Create a tagged GitHub release.
3. Connect/enable the repository in Zenodo.
4. Archive the release.
5. Add the resulting DOI badge and preferred citation to the README.
6. Use the concept DOI where appropriate for all versions.

Do not create a DOI for a misleading placeholder release.

## Suggested release evidence bundle

- demo video,
- three public case studies,
- benchmark methodology/results,
- test report,
- architecture diagram,
- privacy model,
- citation file,
- checksum,
- changelog.

## Success criterion

A researcher or institutional reviewer should be able to answer these questions quickly:

- What problem does Author Focus solve?
- What is different from a normal AI writer?
- What runs locally?
- What evidence is checked?
- What remains under researcher control?
- What has actually been tested?
- How can the software be cited or evaluated?
